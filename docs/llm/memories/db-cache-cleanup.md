# DB Cache Cleanup (verified 2026-07-18)

Archived durable notes from [`../teamlead-memory.md`](../teamlead-memory.md) (extracted 2026-07-18). See the live compact memory there for cross-cutting rules and workflow lessons.

- **YES, cleanup exists.** `CacheRepository.clearOldCacheEntries(ttl, cacheType=None)` at `internal/database/repositories/cache.py:321` does `DELETE FROM cache WHERE (:cacheType IS NULL OR namespace = :cacheType) AND updated_at < :cutoffTime` where `cutoffTime = now − ttl`.
- **Triggers** (both in `HandlersManager`, `internal/bot/common/handlers/manager.py`): (1) **weekly cron** — `_dtCronJob` fires every 60s via `QueueService._cronJobHandler`, weekly gate `nowMinutes==0 and nowHour==0 and nowWDay==0` (Monday 00:00 UTC) → `_cleanupOldData()`; (2) **on shutdown** — `_dtOnExit` → `_cleanupOldData()`. (Line numbers intentionally omitted — they rot on adjacent edits; locate by method name.)
- **`_cleanupOldData()`** (`HandlersManager._cleanupOldData()`): per-namespace cache cleanup — `clearOldCacheEntries(ttl=CACHE_CLEANUP_DEFAULT_TTL_SECS)` (365 days) for ALL namespaces, then a loop over `AGGRESSIVE_CLEANUP_CACHE_TYPES = (WEATHER, YANDEX_SEARCH, URL_CONTENT, URL_CONTENT_CONDENSED)` calling `clearOldCacheEntries(ttl=CACHE_CLEANUP_AGGRESSIVE_TTL_SECS, cacheType=<each>)` (7 days) for those fast-staling namespaces, then `delayedTasks.cleanupOldCompletedDelayedTasks(ttl=DELAYED_TASKS_CLEANUP_TTL_SECS)` (30 days), finally `DatabaseBayesStorage(self.db).cleanupOldTokens(BAYES_TOKEN_CLEANUP_RULES)` — purges old/rare `bayes_tokens` rows across ALL chats. Constants defined near the top of `manager.py`.
- **`cache` table has NO dedicated expiry column** — expiry is computed dynamically as `updated_at + ttl`, both on cleanup AND on read (`getCacheEntry`, cache.py:217-230). Migration 012 added `idx_cache_updated_at` "for TTL cleanup".
- **`cache_storage` table is EXEMPT** (intentional). It's the `CacheService` persistence store (chat settings, chat info, topics, admins) — saved on write, loaded on startup, flushed on exit. Only per-key `unsetCacheStorage` deletes rows; no age-based purge. Has an `updated_at` column a future cleanup COULD use.
- **`CacheType` namespaces** (`internal/database/models.py:399`): `WEATHER`, `GEOCODING`, `YANDEX_SEARCH`, `URL_CONTENT`, `URL_CONTENT_CONDENSED`, `GM_SEARCH`, `GM_REVERSE`, `GM_LOOKUP`. Accessed via `GenericDatabaseCache` (`internal/database/generic_cache.py`). **GM = Geocode Maps (NOT Google Maps)** — corrected 2026-07-15.
- **Cache cleanup TTLs** (`HandlersManager._cleanupOldData()`): changed 2026-07-15 from single 90-day-all to per-namespace: 365 days for ALL namespaces (default floor), then 7 days for `WEATHER`/`YANDEX_SEARCH`/`URL_CONTENT`/`URL_CONTENT_CONDENSED` (fast-staling). 30-day `delayedTasks` cleanup unchanged. Constants: `CACHE_CLEANUP_DEFAULT_TTL_SECS` (365d), `CACHE_CLEANUP_AGGRESSIVE_TTL_SECS` (7d), `DELAYED_TASKS_CLEANUP_TTL_SECS` (30d), `AGGRESSIVE_CLEANUP_CACHE_TYPES` tuple.
- **Bayes tokens cleanup** (added 2026-07-15): the fourth `_cleanupOldData()` step. `DatabaseBayesStorage.cleanupOldTokens(rules)` at [`internal/database/bayes_storage.py`](../../../internal/database/bayes_storage.py) runs one `DELETE FROM bayes_tokens WHERE updated_at < :cutoffTime AND total_count <= :maxCount` per rule in `BAYES_TOKEN_CLEANUP_RULES` (defined near the top of `internal/bot/common/handlers/manager.py`). Default rules: `total_count <= 1` older than 90 days, OR `total_count <= 2` older than 180 days. Deletes across ALL `chat_id`s. Returns `True`/`False`. NOTE: `DatabaseBayesStorage` is a separate class instantiated as `DatabaseBayesStorage(self.db)` — NOT a `self.db.<name>` repository. Sibling `cleanupRareTokens(minCount, chatId=None)` on the same class is unrelated to this cron path. Manual stopword-token removal (one-off, not part of the cron) lives in [`scripts/delete_stopwords.py`](../../../scripts/delete_stopwords.py) — see [`memories/db-maintenance-scripts.md`](db-maintenance-scripts.md).
- **On-demand full-namespace wipe** (not expiry): `CacheRepository.clearCache(cacheType)` (cache.py:291-319) ← `GenericDatabaseCache.clear()`.
- **In-memory GC does NOT touch DB:** `DictCache._cleanupExpired`/`_evictOldest` (`lib/cache/dict_cache.py:109,126`) and `CacheService.LRUCache` evict-on-overflow (`internal/services/cache/service.py:165`) drop from RAM only; `cache_storage` rows persist independently.
- **Test coverage** (added 2026-07-15): `clearOldCacheEntries` is tested by `TestClearOldCacheEntries` (5 tests, per-namespace TTL, ttl=0, boundary checks) in `tests/database/repositories/test_cache_repository.py`. `cleanupOldTokens` is tested by `TestCleanupOldTokens` (7 tests, rule boundaries, cumulative rules, empty rules) in `tests/database/test_bayes_storage.py`. `_cleanupOldData()` is tested by `TestCleanupOldData` (4 tests, mock-verified call sequence) in `tests/bot/common/handlers/test_manager.py`. The actual `_dtCronJob`/`_dtOnExit` trigger methods that call `_cleanupOldData()` remain untested directly.
