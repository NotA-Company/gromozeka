# lib/ai sessionId contract & domain design (2026-09-20)

Archived durable notes from [`teamlead-memory.md`](../teamlead-memory.md) (extracted 2026-09-26). See the live compact memory there for cross-cutting rules and workflow lessons.

## sessionId contract for lib/ai calls (audited 2026-09-20 — HISTORICAL SNAPSHOT; superseded by the completed implementation two sections down)

- Transport is a ContextVar (`_requestSessionIdVar`, `lib/ai/abstract.py:47`), set/reset by 4 `AbstractModel` wrappers (`generateText`/`generateImage`/`generateStructured`/`generateEmbeddings`, keyword-only `sessionId: Optional[str] = None`). Always-set-even-None + finally-reset is load-bearing (no stale-session leak across asyncio tasks). All 6 `LLMService` methods accept and forward `sessionId` verbatim; none synthesize a default.
- Sole consumer: `OpencodeGoModel._getSessionId()` (`lib/ai/providers/opencode_go_provider.py:88-106`) → `x-opencode-session` header. Fallback chain: request sessionId → provider config `session_fallback` → `DEFAULT_SESSION_ID = "gromozeka"`. Missing sessionId NEVER errors — it silently funnels all conversations into one shared prompt-cache/sticky-routing bucket. All other providers ignore sessionId.
- Canonical generator: `BaseBotHandler.getLLMRequestSessionId()` (`internal/bot/common/handlers/base.py:736-765`) → `gromozeka-<chatId>-<rootMessageId.asStr()>` (chat + thread root; `gromozeka-` prefix appears nowhere else by design). Do NOT confuse with `SandboxHandler.getSessionId()` (`chat#{chatId}`, Docker-sandbox identity, never touches lib/ai) or `chatLLM#{chatId}` rate-limiter key.
- Audit result: only 2 proper production sites — `llm_messages.py:225` and `:1061`, both via `await self.getLLMRequestSessionId(ensuredMessage)`. ~30 omission sites (None): base.py condense ×2 + `_parseImage`; llm_messages generateImage + random-condense; divination ×4; media ×4; summarization; yandex_search; user_memories ×5; chat_search ×2 embeddings + a direct `model.generateEmbeddings` bypass at `chat_search.py:1327-1330` (no sessionId AND no consumerId/stats); message_preprocessor; dev_commands `llmReplayCommand`. Scripts without sessionId: check_condensing, check_image_parsing, check_structured_output, check_tool_calling, run_llm_debug_query, reproduce_layout_extraction. `lib/ext_modules/grabliarium` uses lib/ai INDIRECTLY (initial "zero usage" was a gitignore artifact — see next section). Materiality gate: omissions only bite when the resolved model is on the opencode-go provider; embedding omissions currently no-op (fastembed/YC don't read the ContextVar) but are contract-nonconformant.

## grabliarium LLM seam + sessionId domain design (2026-09-20; COMPLETE — all gates passed)

- Grabliarium seam: `grabliarium.py:183` → `LLMService.getInstance().getLLMManager()` injected into `ArticleProcessor` (with `ai-model`/`ai-fallback-model` read at `:80-81` from per-env `grabliarium-defaults.toml`; enabled=true only in prod-*). Single generation site: `article_processor.py:534-539` calls `AbstractModel.generateText` directly — no sessionId, no consumerId (bypasses LLMService generation entirely; no chat-settings/tier/rate-limit plumbing). Fallback model `opencode/qwen3.8-flash` is opencode-go → lands in shared "gromozeka" bucket. Identity in scope at the call: article_id/post_id/project_id (chatId/topicId exist upstream but aren't forwarded into `_generateDescription`).
- Proposed domain taxonomy (architect, unimplemented): **D1** conversation/thread — keep `getLLMRequestSessionId` (base.py:938/956, llm_messages.py:409/938, media.py:176); **D2** one-shot content — `gromozeka-media-<fileUniqueId>` / `gromozeka-url-<sha256(url)[:16]>` / `gromozeka-layout-<id>` (base.py:1431, media.py:535, yandex_search.py:529, divination.py:1130); **D3** feature-flow — `gromozeka-<feature>-<chatId>-<messageId>`, discovery content-keyed instead (divination 693/737/1034, media 664/696, summarization 278, dev_commands 1019 with `dev-` tag); **D4** user memory store — `gromozeka-memory-<chatId>-<userId>-<threadId>` (user_memories.py:1296; strongest multi-round affinity win after D1); **D5** background/embeddings (deferred); **D6** scripts — `gromozeka-script-<name>`; ext modules — `gromozeka-<moduleName>-<flowIdentity>`. Only persistent identifiers allowed (never uuids/runIds — must be stable across restarts).
- Placement proposal: new `lib/ai/session.py` — `buildSessionId(*components)` / `sanitizeSessionIdComponent` / `hashSessionIdComponent`, token-safe charset, 128-char cap (x-opencode-session is an HTTP header value). Reimplement `getLLMRequestSessionId` on top, byte-identical (incl. negative group chatIds → today's `gromozeka--100…` compat shape). Plus `LLMService` auto-fallback `gromozeka-auto-<chatId>` + DEBUG log when sessionId=None (condenseContext has no chatId → derive from consumerId).
- `chat_search.py:1330` direct-model bypass: fix by routing through `LLMService.generateEmbedding` (recovers consumerId stats; `doRateLimit=False` — rate already gated at :1309).
- Embeddings stance: deliberately skip this pass (no provider consumes sessionId there); revisit when a session-consuming provider gains embeddings.
- Side finding: condenseContext handler sites also omit `consumerId` — add `consumerId=str(chatId)` in the same edit.
- Migration order: P0 session.py + auto-fallback → P1 D1 sites + multi-round loops (user_memories 1296, divination 1034) + bypass fix → P2 remaining one-shots → P3 scripts.
- DECIDED by user (2026-09-20): (1) `gromozeka-auto-` LLMService fallback ACCEPTED (with DEBUG log); (2) embeddings deferred ACCEPTED; (3) `dev-` tag split ACCEPTED (`llmReplayCommand` → `gromozeka-dev-<chatId>-<messageId>`, `llm_test_command` keeps conversation session). D6 AMENDED: script session ids carry script-start timestamp → `gromozeka-script-<name>[-<model>]-<startTs>` (UTC `%Y%m%dT%H%M%SZ`, computed once per run — per-run bucket, no cross-run cache pollution).
