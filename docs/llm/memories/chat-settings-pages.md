# ChatSettingsPage System (verified 2026-07-21)

Archived durable notes from [`teamlead-memory.md`](../teamlead-memory.md) (extracted 2026-09-02). See the live compact memory there for cross-cutting rules and workflow lessons.

Source: `internal/bot/models/chat_settings.py` (`ChatSettingsPage` IntEnum, `getName()`, `minTier()`, `next()`).

- **Load-bearing invariant: enum declaration order MUST stay tier-monotonic non-decreasing** — FREE pages first, then PAID, then FRIEND, then BOT_OWNER, then BOT_OWNER_SYSTEM. Reason: `internal/bot/common/handlers/configure.py:291-301` does `page = ChatSettingsPage(...); while not chatTier.isBetterOrEqualThan(page.minTier()): page = page.next()` for the `/settings` entry point — walks FORWARD in enum order until it hits a tier-eligible page. If a higher-tier page precedes a lower-tier one, a low-tier user lands on a too-high page (or hits `None` → AttributeError). Current enum (verified 2026-07-21 after `LLM_BASE` was retired): `STANDARD, EXTENDED, SPAM, LLM_MODELS, LLM_PROMPTS` (all FREE) → `LLM_PAID, PAID` → `FRIEND` → `BOT_OWNER, BOT_OWNER_SYSTEM`. (10 members; `LLM_BASE` was removed and its 11 former entries redistributed to `LLM_MODELS`/`LLM_PROMPTS`/`EXTENDED`.)
- **Page integer values are EPHEMERAL — never persisted.** They flow only as inline-keyboard callback payloads (`ButtonDataKey.Page` → `ChatSettingsPage(value)`). No DB column, no migration. Safe to renumber/reorder (subject to the tier-monotonic invariant above) without a schema migration.
- **Two-tier access gating — TYPE-DEPENDENT:**
  - **PRIMARY gate (all types):** `page.minTier()` — checked on the page-button render (`configure.py:337`), the entry-point walk (`configure.py:292`), the per-setting read filter (`base.py:283` — `settingTier = settingsInfo[k]["page"].minTier()`), and the per-setting edit gate (`configure.py:690`). Lowering a setting's page to a lower-tier page immediately widens BOTH readability AND editability to that lower tier.
  - **SECONDARY gate (MODEL / IMAGE_MODEL only):** `configure.py:713-724` on write AND `base.py:294-302` on read — drops the setting value if the resolved model's tier exceeds chat tier, falling back to currentValue/None. So lowering a MODEL setting's page (e.g. `FALLBACK_MODEL` LLM_PAID→LLM_MODELS) widens VISIBILITY but NOT actual model usage (still gated by the model's own tier).
  - **STRING / BOOL / INT / FLOAT have NO secondary gate** — lowering the page is a direct privilege escalation. This is why `MEMORY_REFINE_SYSTEM_PROMPT` moving `BOT_OWNER_SYSTEM → LLM_PROMPTS` was a Critical review finding: FREE chats could rewrite the refinement system prompt with nothing else stopping them.
- **`ChatSettingsPage.next()` semantics** (`chat_settings.py:257-270`): returns member at `index+1` in declaration order, or `None` at end. No wraparound. Every `minTier()` match-arm MUST exist (raises `NotImplementedError` otherwise) — when adding a new page, all three of (enum member, `getName()` arm, `minTier()` arm) must land together in source-declaration order.
- **`_chatSettingsInfo` dict source ordering is by TOPIC, not by page** — models block, prompts block, system block, spam block, bayes, etc. Page assignments now interleave (e.g. LLM_MODELS / LLM_PROMPTS / BOT_OWNER_SYSTEM entries are scattered). That divergence is intentional/cosmetic; do NOT reorder the dict by page — too many docs cite line numbers. Topic grouping is the prevailing convention.
- **Test breakage surface from page changes:** `tests/integration/test_divination_chat_settings.py` is the only test that hardcodes per-setting page expectations (assertions on `info[KEY]["page"] is ChatSettingsPage.X`). No test pins enum count/order (`list(ChatSettingsPage)` / `len(...)` / `expectedPages` — none exist). When changing a setting's page, grep `tests/` for `ChatSettingsPage\.<OLD_PAGE>` and update.
- **Doc surfaces that carry per-setting page claims** (must be synced on page reassignment): `docs/llm/configuration.md` (the big settings table), `docs/llm/memories/llm-messages-handler.md`, `docs/llm/memories/user-memory-refinement.md`, `docs/llm/memories/user-memories.md`, `.agents/skills/add-chat-setting/SKILL.md` (page-table at line ~80 — missing `LLM_MODELS`/`LLM_PROMPTS` rows as of 2026-07-21).
- **`LLM_BASE` page was RETIRED 2026-07-21.** User's design decision: consolidate all non-embedding LLM model pickers onto `LLM_MODELS` (free tier — visibility widening of several former PAID/FRIEND model pickers is intentional), all prompt strings onto `LLM_PROMPTS`, and the two stragglers went elsewhere: `RANDOM_ANSWER_PROMPT` → `LLM_PROMPTS`, `MEMORY_ENABLED` → `EXTENDED`. Final enum has 10 members (see invariant above).
- **Convention under memory `42b5e19d`**: "refinement prompt copy goes on `BOT_OWNER_SYSTEM`" — `MEMORY_REFINE_SYSTEM_PROMPT` and `MEMORY_REFINE_USER_PROMPT_TEMPLATE` were deliberately locked together and remain on `BOT_OWNER_SYSTEM`. Any move MUST keep them on the same page (they are consumed together at `internal/bot/common/handlers/user_memories.py:1273`).
