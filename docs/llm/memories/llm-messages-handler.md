- **`EnsuredMessage` uses `__slots__`** (~line 355 in `internal/bot/models/ensured_message.py`) — its methods (`toModelMessageList`, `toModelMessage`, `updateMediaContent`, `getEnsuredRepliedToMessage`) CANNOT be overridden on instances via `mock.method = ...`. Patch at the CLASS level via `patch.object(EnsuredMessage, methodName, ...)` inside an `ExitStack`, and keep the stack entered with `with stack:` for the handler call. This is the pattern actually used in the live tests (see `_wireReplyPath` / `_wireMentionPath` / `_wireCondensePath` helpers — lines 608, 638, 1499).
- **`_sendLLMChatMessage` JSON-unwrap is gated on `llmMessageFormat != LLMMessageFormat.JSON`** (~line 329). The unwrap is a HEURISTIC for TEXT-format chats where the model emits JSON despite being asked for text. In explicit JSON-format chats, the unwrap is skipped — so any "runs after JSON unwrap" downstream logic (e.g. `<skip>` sentinel detection) does NOT benefit from unwrap in JSON mode. This is a non-obvious asymmetry; check the format gate before assuming unwrap runs universally.
- **`<media-description>` extraction** (`_sendLLMChatMessage`, ~lines 354-373): regex `^(.*?)<media-description>(.*?)</media-description>(.*?)$` with `re.DOTALL`. Gate `startswith("<media-description>") OR endswith("</media-description>")` on the trimmed/wrapper-stripped text — INTENTIONAL: only captures tags at start or end of message, NOT pure-middle position (e.g. `text<tag>foo</tag>text` is left untouched). Group 1 = leading text, group 2 = image prompt, group 3 = trailing text; `lmRetText = g1.strip() + g3.strip()`. Because of the gate, g1 or g3 is always empty (tag is at one end or the other, not both). Only ONE tag per message is handled (non-greedy group 2 stops at first close tag; second tag survives as literal text) — INTENTIONAL. Block is gated on `llmMessageFormat != JSON`. Historical note: an earlier version had `r"^<media-description>(.*?)</media-description>(.*?)"` with no end anchor, so the trailing `(.*?)` always captured empty and silently discarded any text after the close tag — fixed in the random-answer-feature pass (2026-07-05) to the current three-group shape with explicit `$` anchor.
- **Abstention sentinel INVARIANT** (`_sendLLMChatMessage`, ~line 394): `if imagePrompt is None and lmRetText.strip().strip("`").strip() in ("<skip>", ""):` → `SKIPPED_BY_MODEL`. The `imagePrompt is None` gate is CRITICAL — without it, tag-only image requests (`<media-description>foo</media-description>` with empty caption) get misclassified as abstention (empty `lmRetText` triggers the `""` clause) and the image is silently dropped. The sentinel must run AFTER `<media-description>` extraction (so `imagePrompt` is populated) but BEFORE the image-gen branch (so `<skip>` never triggers image gen). The `""` (empty-string) clause was added separately to handle empty-TRUNCATED_FINAL output (Qwen3 budget exhaustion → `telegram.BadRequest: Message text is empty`) — see [`memories/llm-empty-truncated-final.md`](llm-empty-truncated-final.md). Both clauses coexist safely BECAUSE of the `imagePrompt is None` guard.
