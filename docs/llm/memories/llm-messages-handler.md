- **`EnsuredMessage` uses `__slots__`** — its methods (`toModelMessageList`, `toModelMessage`, `updateMediaContent`, `getEnsuredRepliedToMessage`) CANNOT be overridden on instances via `mock.method = ...`. Patch at the CLASS level via `patch.object(EnsuredMessage, methodName, ...)` inside an `ExitStack`, and keep the stack entered with `with stack:` for the handler call. Reusable test pattern for any test that needs to drive `handleRandomMessage`/`handleReply`/`handleMention` with mocked `EnsuredMessage` behavior.
- **`_sendLLMChatMessage` JSON-unwrap is gated on `llmMessageFormat != LLMMessageFormat.JSON`** (~line 320). The unwrap is a HEURISTIC for TEXT-format chats where the model emits JSON despite being asked for text. In explicit JSON-format chats, the unwrap is skipped — so any "runs after JSON unwrap" downstream logic (e.g. `<skip>` sentinel detection) does NOT benefit from unwrap in JSON mode. This is a non-obvious asymmetry; check the format gate before assuming unwrap runs universally.
- **Pre-existing bug in `<media-description>` regex** (`llm_messages.py` `_sendLLMChatMessage`, regex `r"^<media-description>(.*?)</media-description>(.*?)"` with `re.DOTALL`): the trailing group `(.*?)` is non-greedy with no end anchor, so it ALWAYS captures empty — e.g. `<media-description>foo</media-description>bar` yields `imagePrompt="foo"` and `lmRetText=""`, discarding `"bar"`. Out of scope for the random-answer feature (flagged 2026-07-05, not fixed); likely fix is `(.*?)` → `(.*)` at the end.
- **`getThreadByMessageForLLM` returns a fresh list** (`ret = [...]` then `ret.extend(...)` — no caching), so callers can safely rebind slots (`storedMessages[0] = ...`) or slice-rebuild without corrupting shared state. Note `storedMessages` is typed `Sequence[ModelMessage]` (no `__setitem__`), so pyright rejects item-assignment — use slice-rebuild `[newMsg, *storedMessages[1:]]` or mutate `.content` in place.
- **`<media-description>` extraction** (`_sendLLMChatMessage`, ~lines 345-355): regex `^(.*?)<media-description>(.*?)</media-description>(.*?)$` with `re.DOTALL`. Gate `startswith("<media-description>") OR endswith("</media-description>")` — INTENTIONAL: only captures tags at start or end of message, NOT pure-middle position (e.g. `text<tag>foo</tag>text` is left untouched). Group 1 = leading text, group 2 = image prompt, group 3 = trailing text; `lmRetText = g1.strip() + g3.strip()`. Because of the gate, g1 or g3 is always empty (tag is at one end or the other, not both). Only ONE tag per message is handled (non-greedy group 2 stops at first close tag; second tag survives as literal text) — INTENTIONAL. Block is gated on `llmMessageFormat != JSON`. Fixed 2026-07-05 (was: trailing `(.*?)` with no anchor, silently discarded all trailing text).
- **Abstention sentinel INVARIANT** (`_sendLLMChatMessage`, ~line 372): `if imagePrompt is None and lmRetText.strip().strip("`").strip() in ("<skip>", ""):` → `SKIPPED_BY_MODEL`. The `imagePrompt is None` gate is CRITICAL — without it, tag-only image requests (`<media-description>foo</media-description>` with empty caption) get misclassified as abstention (empty `lmRetText` triggers the `""` clause) and the image is silently dropped. The sentinel must run AFTER `<media-description>` extraction (so `imagePrompt` is populated) but BEFORE the image-gen branch (so `<skip>` never triggers image gen). The `""` (empty-string) clause was added separately to handle empty-TRUNCATED_FINAL output (Qwen3 budget exhaustion → `telegram.BadRequest: Message text is empty`) — see [`memories/llm-empty-truncated-final.md`](llm-empty-truncated-final.md). Both clauses coexist safely BECAUSE of the `imagePrompt is None` guard.
