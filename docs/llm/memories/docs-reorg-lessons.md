# Docs Reorg Lessons (2026-07-04)

Archived durable notes from [`../teamlead-memory.md`](../teamlead-memory.md) (extracted 2026-07-18). See the live compact memory there for cross-cutting rules and workflow lessons.

- When bulk-moving docs with `git mv`, sibling-relative links INSIDE the moved files are the easy-to-miss gap. A dev reported "fixed relative links" but Gate 1 review caught 3 unfixed sibling links in a retained doc pointing to a moved companion. Always grep the moved files' OWN content for sibling refs after relocation.
- Code-doc comments (`*.py` docstrings, migration module docstrings) and `tests/**/*.md` golden-doc files also reference design/plan docs — these are easy to miss because they're outside `docs/`. As of 2026-07-18 the hotspots are `internal/**/*.py` (16 refs, e.g. `internal/bot/common/handlers/user_memories.py`, `internal/database/migrations/versions/migration_02*`) and `tests/**/*.py` + `tests/**/*.md` (6 refs); `lib/` is currently clean. Grep the whole tree for `docs/plans/` and `docs/design/` paths, not just `docs/` — the surface drifts as features land.
- `configs/00-defaults/*.toml` files carry doc-path references in comments (e.g. `# See docs/archive/plans/chat-history-search-plan.md` in `search-history.toml` and `bot-defaults.toml`, `# See docs/llm/memories/user-memories.md` in `user-memory.toml`). These need repointing too.
- A status-line-only edit can create an internal contradiction if the doc has a separate `Scope:` line making similar claims — reconcile ALL status/scope/phase headers, not just the one flagged.
- For docs-only reorgs: `make check-docs` is the primary gate (catches broken local markdown links via `scripts/check_docs.py`); add `make lint` if the reorg also touches comment-only `.py` edits (black/isort are no-ops on `.md` and on comment-only `.py`). `make test` is not needed — docs-only changes don't alter runtime behavior. See [`doc-link-fix-campaign.md`](doc-link-fix-campaign.md) for the full link-checker conventions.
