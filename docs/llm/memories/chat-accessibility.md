# Chat Accessibility & getChatAdmins Graceful Degradation (2026-08-12)

Archived durable notes from [`teamlead-memory.md`](../teamlead-memory.md) (extracted 2026-09-02). See the live compact memory there for cross-cutting rules and workflow lessons.

- **`getChatAdmins` graceful degradation (2026-08-12, IMPLEMENTED):** `TheBot.getChatAdmins` (`internal/bot/common/bot.py`) no longer raises for bot-not-in-chat conditions. On Telegram `Forbidden` (always) and `BadRequest` only when message == `"chat not found"` (other BadRequest re-raised by design); on Max `lib.max_bot.exceptions.NotFoundError` (NOT `AuthenticationError` = global token problem). It logs `logger.warning(...)` with chat id + platform and returns `{}` WITHOUT caching, so a re-added bot retries the live API on the next call. `isAdmin` therefore returns False and `/configure`/`/list_chats` silently exclude the chat instead of crashing. New top-level import: `import lib.max_bot.exceptions as maxExceptions`. Regression tests: `tests/bot/common/test_bot.py` (6 tests; failure paths assert `setChatAdmins.assert_not_called()`). Full suite 3898 passed/11 skipped. Note: transient `NetworkError`/`TimedOut` on both platforms is still UNCAUGHT (different problem class — warrants retry, not silent `{}`); flagged as a separate follow-up.

- **Chat-accessibility tracking (2026-08-12, IMPLEMENTED then USER-SIMPLIFIED):** Bot records per-chat presence in `chat_info.bot_status` so `/configure` and other admin-checking flows no longer crash on chats the bot was kicked from. Migration `026` adds `chat_info.bot_status TEXT NOT NULL DEFAULT 'active'` (COLUMN ONLY — the originally-planned `idx_chat_info_bot_status` index was removed in the simplification; NO `bot_left_at` — user decision). `ChatBotStatus` StrEnum = ACTIVE/INACCESSIBLE only. NO event wiring (no `my_chat_member`/Max events — user decision). **Simplified design (cache-aside, no in-memory set):** `CacheService.isChatInaccessible(chatId)->bool` is ASYNC — cache-aside via `getChatInfo` (in-memory `self.chats` cache first, DB on miss); returns True if the chat is unknown (fail-closed) or `bot_status==INACCESSIBLE`, else False. `markChatInaccessible(chatId)->bool` / `markChatActive(chatId)->bool` (async) read `getChatInfo` → set `bot_status` → persist via `setChatInfo` (cache + DB). `getChatAdmins` short-circuits via `await isChatInaccessible` (skips the platform API; cache-aside so cheap on a cache hit) and marks-on-failure at the catch sites (Telegram `Forbidden`/`BadRequest("chat not found")`, Max `NotFoundError`) → `markChatInaccessible` (preserves the Part-1 no-admin-cache-poison `{}` return). Recovery is preprocessor-only (`MessagePreprocessorHandler.newMessageHandler`: `if await isChatInaccessible(chatId): await markChatActive(chatId)`). **Persistence (SELF-HEAL — 2026-08-12 corrected; the earlier non-clobber framing was wrong):** `ChatInfoRepository.updateChatInfo(..., *, botStatus: Optional[ChatBotStatus] = ChatBotStatus.ACTIVE)` — default is **ACTIVE** (NOT `None`), and `bot_status` is UNCONDITIONALLY in both `values` and `updateExpressions` of the upsert; `None` is not a valid input. `CacheService.setChatInfo` passes `info["bot_status"]` (direct subscript, NOT `.get()`). `ChatInfoDict.bot_status` is **REQUIRED** (not `NotRequired`), and `TheBot.getChatInfo` DOES hardcode `"bot_status": ChatBotStatus.ACTIVE` in BOTH platform branches (`internal/bot/common/bot.py:1168,1190`). Net effect: the every-message refresh path (`BaseBotHandler.updateChatInfo` → `TheBot.getChatInfo` → `setChatInfo` → repo) always writes ACTIVE, so a transient `INACCESSIBLE` set by `markChatInaccessible` self-heals to ACTIVE the next time the bot receives a message from that chat (correct — receipt proves accessibility). `bot_status` is a short-lived "getChatAdmins probe failed" flag, not a permanent state. (An earlier non-clobber design — `botStatus=None`→omit, `info.get(...)`, `NotRequired`, hardcode removed — was prototyped in several memories/docs but NEVER landed in code; the self-heal shape above is the source of truth.) **Removed in the simplification:** `_inaccessibleChats` set, `setChatBotStatus`, `getInactiveChatIds`, `idx_chat_info_bot_status`, `BaseBotHandler.getUserChats` wrapper, `injectDatabase` startup-seed. Chat-list queries `getUserChats`/`getAllGroupChats` take `botStatus` (default ACTIVE = exclude inaccessible; `None` = all) via predicate `(:botStatus IS NULL OR ci.bot_status = :botStatus)`; `/list_chats all` owner branch (`common.py:416`) passes `None` so the owner sees dead chats for diagnostics; all other consumers inherit ACTIVE. DM-block tracking DORMANT. **Nuance:** after the ~12h chat-info refresh writes a bot_status-less dict to cache, `isChatInaccessible` returns False for an INACCESSIBLE chat until the next `getChatAdmins` (Forbidden) re-marks it (self-healing — one extra API call per dead chat per refresh cycle; DB + chat-list filter stay correct). Authoritative design + divergence note: `docs/design/chat-accessibility-tracking.md` (body is historical design rationale; the "Implementation Divergence (2026-08-12)" section near the top documents the simplification). Final: `make test` 3925 passed/0 failed/11 skipped; lint clean; check-docs 0 broken. **Bug-class lesson:** routing a status flip through `setChatInfo`→`updateChatInfo` silently no-op'd because `updateChatInfo` intentionally omitted `bot_status` (non-clobber) — when you write a field through an existing path, verify that path actually persists that field; a "non-clobber" omission becomes "never persisted" for new writers.
